## 修订缘由

当前 Context Gain 无法完全区分以下两种解释：

1. 模型确实利用了有结构、有意义的语言历史；
2. 输入变长后，特征更平滑、统计结构发生变化，或与故事位置相关的慢变化成分增强。

现有 40 s time-shift 控制打断的是 **响应侧时间对应**：它破坏 language feature 与 BOLD response 的正确时间关系，但不会直接破坏刺激侧上下文结构。

本增补新增 **刺激侧上下文控制**，通过固定扰动目标词之前的上下文，检验 Context Gain 是否对完整同故事语言结构敏感。刺激侧控制与 40 s time-shift 分别针对不同替代解释，二者互补，但都不被视为机制性证据。

# §0 配置层改动

## 0.1 condition 维度扩展

V6.3 的拟合键为：

```text
subject × outer_fold × model × H × layer × condition
```

原有 `condition ∈ {normal, shift40}`，本增补扩展为：

```text
condition ∈ {
    normal,
    shift40,
    ctx_shuffle_story,
    ctx_shuffle_block256
}
```

其中 `ctx_shuffle_story` 为 C1（核心刺激侧控制），`ctx_shuffle_block256` 为 C2（扩展性控制，不进入最小必需范围）。

每个 condition 必须独立拟合 scaler、PCA、inner-fold λ、Ridge。不得复用 normal 已拟合对象，也不得通过变换 normal prediction 得到控制条件 prediction。

## 0.2 扰动原则

扰动只作用于目标词 `w_i` 之前的上下文输入。以下内容不变：目标词 `w_i`、目标词顺序、onset / offset、`eligible_h128`、target-word mask、BOLD timeline、fold split、scoring mask。

对每个目标词，模型输入仍为：

```text
perturbed_context[i-H : i] + w_i
```

并继续沿用逐目标窗口状态重置协议：Pythia 不复用 out-of-window KV cache；RWKV 清空 recurrent state；Mamba 重置 SSM/cache；AWD-LSTM 如执行则重置 hidden/cell state。

## 0.3 C1：ctx_shuffle_story（M4S-Core）

### 定义

对每篇故事的完整原始词序列生成一次固定置换 `π_story`，得到同故事 shuffled lexical sequence `s`。对于目标词位置 `i`：

```text
input_C1(i, H) = s[i-H : i] + w_i
```

同一篇故事只生成一次置换；同一置换供所有模型、H、被试共同使用；置换索引落盘；所有后续滑窗都基于该固定序列。

### 索引记号约定（实现必须遵守）

为避免实现歧义，全文统一以下记号：

- `s[j] = w_{π(j)}`，即置换后序列第 `j` 位放的是原始第 `π(j)` 个词；
- `C1_context_slots(i,H) = {i-H, ..., i-1}`，指**置换后序列的槽位**；
- `C1_context_origins(i,H) = {π(j) : j ∈ C1_context_slots(i,H)}`，指这些槽位所承载的**原始位置**；
- `C1_context_words(i,H) = {w_{π(j)} : j ∈ C1_context_slots(i,H)}`，指实际词形。

§2.4 的诊断量一律基于 `C1_context_origins` 与 `C1_context_words`，不得误用 `C1_context_slots`。两者数值完全不同，混用会使诊断失去意义。

### 破坏与保留

C1 主要破坏：原始语序；句法结构；局部语义连贯；指代和事件连续性；真实 preceding context。

C1 保留：同一故事的总体词汇池；故事级词频分布；目标词本身及时间位置；固定序列上的滑窗重叠结构；相邻窗口在索引层面的 H−1 重叠关系。

### 重要限制

C1 不是"打乱后的真实历史"。由于置换覆盖整篇故事，某一目标词的控制上下文可能包含原故事中来自更晚位置的词。因此论文中必须使用以下口径：

> C1 replaces the true preceding context with a fixed same-story shuffled lexical context while preserving the story-level lexical inventory and sliding-window overlap.

不得声称 C1 单独控制了 story-position effect，也不得把它解释为仅破坏语序而保留全部其他信息。

## 0.4 C2：ctx_shuffle_block256（M4S-Extended，可选）

### 定义

将每篇故事切分为不重叠的 256-word blocks，在每个 block 内分别进行固定置换，block 顺序保持不变。目标词输入仍为：

```text
input_C2(i, H) = s_block256[i-H : i] + w_i
```

### block size 的选择与其代价

选择 256 而非 128，是为了避免 block size 与最大上下文 H=128 完全重合、产生人为的设计耦合（若 block=128，H=128 的窗口要么恰好落在一个 block 内、要么恰好跨一条边界，行为在两类窗口间断裂）。

但必须承认这个选择的代价：block=256 时，H=128 的上下文仍是从一个 256 词邻域中抽样，"保留局部词汇来源"只是**弱意义上**的保留。因此 C1 与 C2 的对比是**扰动强度的连续梯度**，不是"局部保留 vs 不保留"的二分。论文中只能按 §7.4 判读表的口径描述，不得表述为已分离词汇与语序的独立贡献。若日后要加强这一对比，应另立版本讨论 block 尺度的系统扫描，不在本轮范围内。

### 作用

C2 相比 C1 更大程度保留：局部词汇来源；故事大尺度位置；固定滑窗重叠。但 C2 仍会破坏：语序；句法；指代；事件结构；自然语言分布。

C1 与 C2 的比较只允许被解释为：

> 对"局部词汇来源是否被保留"这一扰动强度差异的描述性敏感性分析。

不得解释为已经独立分离了句法、语义和词汇内容的因果贡献。

### block boundary 记录

如执行 C2，必须记录：每个 H 下跨 block boundary 的目标窗口比例；各故事的 boundary-crossing count；C1/C2 的置换 hash。

## 0.5 C3：ctx_crossstory（M4S-Optional）

上下文来自另一篇故事的对应相对位置。该条件不进入本轮核心或扩展范围；若执行，须另立补充条款并冻结 donor-story matching 规则。

## 0.6 禁止逐窗口独立打乱

严禁对每一个目标窗口独立重新随机打乱上下文。正确方式是：

```text
每篇故事生成一次固定扰动序列
→ 在固定序列上滑窗
→ 相邻窗口共享 H−1 个上下文索引
```

逐窗口独立打乱会同时破坏语言结构、窗口重叠、时间平滑与相邻目标表示的连续性。此时 encoding score 的下降无法区分来自语言结构破坏，还是来自特征时间统计结构被额外破坏。

## 0.7 seed 与稳定派生

主 seed 固定为：

```text
ctx_perturb_seed = 20260724
```

不得使用 Python 内置 `hash(story_id)` 派生子 seed，因为其对 str 的结果受 hash randomisation（`PYTHONHASHSEED`）影响，跨进程不可复现。统一使用稳定哈希：

```text
story_seed = int.from_bytes(
    sha256(f"{master_seed}|{story_id}".encode()).digest()[:8],
    "big"
)
```

manifest 至少记录：master seed；story ID；derived story seed；condition；permutation length；permutation file；permutation SHA-256；code commit / tag。

## 0.8 特征缓存

新条件必须使用独立缓存键：

```text
condition
+ perturb_spec_version
+ master_seed
+ permutation_hash
+ H
+ model
+ layer
+ target_set_hash
```

不得覆盖 normal 缓存。新条件缓存落盘后必须再次核验：normal cache hash；target-set hash；permutation hash；layer；H；condition。

## 0.9 有效 TR mask

刺激侧扰动不移动时间轴，因此控制条件必须与 normal 使用逐元素相同的最终评分 mask：

```text
after_100s ∩ FIR_valid
```

执行 `assert np.array_equal(mask_ctx, mask_normal)`，不一致直接 raise。刺激侧条件不添加 `shift_valid`，也不丢弃故事边界 TR。

# §2 实现正确性与特征诊断

## 2.1 硬性实现断言（hard gate）

以下断言用于判断代码实现是否正确，是进入编码前的硬闸门。全部为确定性检查，与结果无关。

**A. 单故事单置换** —— 每个 `(story_id, condition)` 只能对应一个 permutation hash。

**B. 相邻滑窗重叠** —— 对于同一故事、同一 H、相邻目标位置 `i` 与 `i+1`：

```text
ctx_slots(i+1, H)[:-1] == ctx_slots(i, H)[1:]
```

对 C1/C2 均逐故事抽样或全量验证。

**C. 跨模型一致** —— 同一 `(story_id, H, condition)` 的 context slot / origin sequence 在 Pythia、RWKV、Mamba 之间完全相同。

**D. 跨被试一致** —— 刺激特征由共同故事文本决定，因此同一 `(story_id, model, H, layer, condition)` 的特征缓存 key 和 permutation hash 在三被试之间一致；被试差异只存在于 BOLD、ROI 和 encoding fitting。

**E. 目标词未改** —— 逐元素验证 target word、target index、onset、offset、target-set hash。

**F. mask 未改** —— 逐元素验证 normal 与刺激侧条件的 scoring mask 相同。

任何硬断言失败，必须停止后续编码并修正实现。

## 2.2 lag-1 平滑度诊断（描述性）

lag-1 诊断保留，但**不是**单独判定实现对错的依据——窗口重叠的正确性由 §2.1 的确定性断言保证；lag-1 是下游后果，即使实现完全正确，打乱上下文本身也会真实地改变表示统计。

### 计算对象

对每个 `model × H × condition × story`，在 word features 对齐至 TR、Lanczos resampling 完成后、FIR expansion 之前，计算相邻 TR representation 的余弦相似度 `cos(x_t, x_{t-1})`，每篇故事取中位数。可同时补充 mean feature-wise lag-1 correlation，但必须固定计算实现，不得根据结果选择较有利指标。

### 参考量的定义（结果产出前写死）

**必须区分两类区间，不得混用：**

1. **容差带（tolerance band，用于判断"是否异常"）**
   对每个 `model × H`，取 **normal 条件下 story-level 值本身**的分布，报告其中位数、SD、以及 2.5th / 97.5th percentiles。该带描述的是故事之间的自然离散度，是判断 C1/C2 偏离是否超出常态的参照。

2. **精度区间（precision interval，仅用于描述估计不确定性）**
   normal story-level 中位数的 1000 次 story bootstrap 2.5/97.5 百分位。该区间**只**用于说明 normal 中位数本身估计得多准，**不得**用作异常判定阈值。

> 说明：V6.4.1 曾把第 2 类当作异常判定带。该区间随故事数增大而收窄，而 C1 相对 normal 的 lag-1 位移是设计上**预期会发生**的真实变化，二者尺度不匹配，会导致审计标记近乎必然触发、随后被普遍忽略，闸门形同虚设。本版改为以第 1 类作判定、第 2 类仅作描述。

### 主报告量：逐故事配对差值

lag-1 的主要报告量是**配对差值**，而非两个条件各自的边际中位数：

```text
Δlag1(story) = lag1_normal(story) − lag1_C1(story)
```

报告其跨故事中位数与 2.5/97.5 百分位。配对可消除故事长度、语速、体裁带来的异质性，比边际比较更稳。

### 审计触发规则（冻结）

满足以下任一条即触发缓存、索引与 resampling 审计（**仅触发审计，不得据此删除条件、更换 seed 或重设扰动规范**）：

1. `median(Δlag1) > 1.0 × SD_story(lag1_normal)`（同一 model × H 内比较）；
2. C1 的 story-level 中位数落在 normal 容差带 [P2.5, P97.5] 之外；
3. `Δlag1` 的故事级分布出现明显双峰，或存在偏离其自身中位数 3 SD 以上的个别故事。

阈值 `k = 1.0` 是一个约定值而非统计判据，其唯一作用是在看到结果前把"什么叫异常"固定下来；审计结论以 §2.1 的确定性断言为准。

### 判读

- 硬性索引断言通过、但 lag-1 下降：记录为扰动后表示统计变化，不自动视为实现错误；
- 硬性索引断言失败：视为实现错误，停止；
- 触发上述任一审计条件：执行审计并记录结论，但不得仅因结果不利更换 seed 或扰动规则。

论文中必须同时报告：normal lag-1（中位数 + 容差带）；C1 lag-1；如执行则 C2 lag-1；`Δlag1` 的故事级分布；是否触发审计及审计结论。

## 2.3 OOD 退化的 H 依赖性诊断（M4S-Extended，强烈建议）

### 为什么需要

打乱上下文对语言模型是分布外输入，这一点在 Limitations 中已声明。但更关键的一层是：**若 OOD 退化程度本身随 H 增加而累积**（128 个乱序词比 8 个乱序词"更不像自然语言"），则退化就是 H 依赖的，会直接混入 `Δr_total^C1`，从而也混入配对差值 `D_m` 与交互量 `I_MP`——**配对不能消除它**。这是本控制最深的一处弱点，必须主动检查并报告，而不是等被问到。

### 指标的主次（本版调整）

三项指标对"退化"的指示力并不相同，必须分主次报告：

**主指标（表示层退化）**

1. 目标位置隐表示的 **L2 范数**中位数；
2. PCA 前特征矩阵的**有效维度**（participation ratio；同时记录 evr@100）。

这两项直接刻画表示本身的几何性质是否随 H 塌缩或膨胀，与"退化"的对应较直接。

**辅助指标（预测信息量）**

3. 语言模型在目标 raw word 上的 negative log-likelihood（若该 checkpoint 可得）。

> NLL 必须谨慎解读：上下文被打乱后 NLL 上升，可能来自 **(a) 上下文携带的预测信息减少**——这正是本控制**想要**造成的效果，不是混淆；也可能来自 **(b) 输入 OOD 导致模型整体行为退化**——这才是混淆项。NLL 无法区分二者。因此 NLL 只作辅证：当 NLL 的 H 依赖变化与 L2 范数、有效维度的变化方向一致时，可加强"存在退化"的判断；单靠 NLL 上升不足以断定退化。

### 目标词 NLL 的冻结定义

目标 raw word `w_i` 若被 tokenizer 分成 `K_i` 个 subtokens `t_{i,1}, ..., t_{i,K_i}`，主指标固定为：

```text
NLL_sum(w_i) = - Σ_{k=1..K_i} log p(t_{i,k} | context, t_{i,1:k-1})
```

同时记录补充指标：

```text
NLL_mean(w_i) = NLL_sum(w_i) / K_i
```

纪律如下：

- `NLL_sum` 为主定义，`NLL_mean` 仅用于检查 subtoken 数量影响；
- 目标词由一个 subtoken 构成时，两者相同；
- **本轮不做跨架构的绝对 NLL 排名**，理由是该量不进入任何 contrast、与 `D_m`/`I_MP` 无关，报告它只会引入无关的解读分歧；
  （需要说明的是：Pythia、RWKV-4 与 Mamba 共用 GPTNeoX tokenizer 与词表，事件空间相同，跨 checkpoint 的 NLL 在原理上是可比的。因此不得以"词表不同、概率不可比"为由解释这条纪律——那是不成立的理由。）
- 对无法稳定获得目标词概率的 checkpoint，须在 manifest 中标记 `not_available`，不得使用替代模型的 NLL 填补。

### 比较方式

比较 `C1(H=8)` → `C1(H=128)` 的指标变化，并与 `normal(H=8)` → `normal(H=128)` 的相应变化对照。核心问的是**变化幅度之差**，不是绝对水平。

### 判读

- 若 C1 下的 H 依赖变化幅度与 normal 相当（尤其两项主指标）：可写明"未发现 OOD 退化随 H 系统性加剧的证据"，`D_m`/`I_MP` 的解释力相应增强；
- 若 C1 下主指标变化明显更大：必须在 Results 与 Limitations 中明确写出 `D_m` 与 `I_MP` 受此混淆影响，并把结论下调为"方向性提示"；
- 若仅 NLL 变化更大而两项主指标相当：按上一条的**弱化版本**处理——记录为"可能存在预测信息量变化，但未见表示层退化的独立证据"，不单独据此下调结论；
- 无论哪种结果都必须报告，不得只在有利时呈现。

若本诊断未执行（降级至 L2/L3），Limitations 中必须写明该混淆未经检查。

## 2.4 C1 目标来源词与词形重复诊断（M4S-Core，必做）

### 为什么需要

C1 对整篇故事进行一次全局置换。对某个目标位置 `i`，其控制窗口可能包含：

1. 原故事中目标 occurrence 自身对应的原始位置；
2. 与目标 raw word 相同的其他 occurrence；
3. 对专有名词或低频词而言，额外的显式词汇提示。

这一现象不应通过"逐目标排除"来修正，因为逐目标修改会破坏固定序列和 H−1 滑窗重叠。正确处理是保持 C1 规范不变，并在结果解释前量化该现象。

### 固定诊断量

按 §0.3 的记号，对每篇故事、每个 H 记录：

```text
origin_inclusion(i,H) = 1{ i ∈ C1_context_origins(i,H) }
origin_inclusion_rate(H) = mean_i origin_inclusion(i,H)

form_repetition(i,H)  = 1{ w_i ∈ C1_context_words(i,H) }
form_repetition_rate(H) = mean_i form_repetition(i,H)
```

另按目标词在该故事中的频次分层报告：hapax（story-frequency = 1）；story-frequency 2–5；story-frequency > 5。

### 预期量级（结果产出前写死，用于判断实现是否正常）

在均匀随机置换下，对故事长度 `N`：

```text
E[origin_inclusion_rate(H)] ≈ H / N
E[form_repetition_rate(H) | story-frequency = f] ≈ 1 − (1 − H/N)^f
```

以本数据集的平均故事长度 `N ≈ 156,759 / 83 ≈ 1,889` 词估算：

| H | origin inclusion | form repetition (f=1) | (f=5) | (f=50) |
|---|---|---|---|---|
| 8 | ≈ 0.4% | ≈ 0.4% | ≈ 2.1% | ≈ 19% |
| 32 | ≈ 1.7% | ≈ 1.7% | ≈ 8.2% | ≈ 58% |
| 128 | ≈ 6.8% | ≈ 6.8% | ≈ 30% | ≈ 97% |

逐故事实际值须按各自 `N` 计算；上表只是量级预期。**实测值大幅偏离该预期即提示置换或索引实现有误**，应回到 §2.1 排查，而不是接受数值继续。这也是本诊断的第二个用途。

由上表可见：在 H=128 时，高频词（功能词、故事主角名）的词形几乎必然出现在控制窗口中。这是 C1 的固有性质，不是实现缺陷。

### 偏差方向声明（结果产出前写死）

该现象在 H=128 上远强于 H=8，因此为 C1 在长窗口下提供了短窗口所没有的额外词汇提示。其**方向性后果是确定的**：

```text
抬高 r128^C1  →  抬高 Δr_total^C1  →  压低 D_m = Δr_total^normal − Δr_total^C1
```

也就是说，该混淆**系统性地偏向"控制未显示依赖真实语言结构"这一结论**。因此：

- 若 `D_m` 仍显著为正，结论比表面看起来更稳——该偏差是在与之相反的方向上起作用；
- 若 `D_m` 接近 0，**不能**直接断定 Context Gain 不依赖语言结构，必须同时报告本诊断的量级并说明该偏差的存在；
- 对交互量 `I_MP = D_Mamba − D_Pythia`，该偏差在两模型上同时存在，一阶上部分抵消；但抵消是否完全取决于两个 checkpoint 利用词形重复线索的程度是否相同，这一点本设计无法验证，须在 Limitations 中如实写明。

以上方向声明必须在看到结果之前写入配置，事后不得修改。

### 判读纪律

- 这些比例属于控制条件描述，不作为剔除目标词的依据；
- 实测值大幅偏离 §2.4 预期表 → 触发 §2.1 实现排查；
- 不得在看到比例后对特定词类、故事或 H 做事后排除；
- 如未来需要避免该问题，应另立版本设计 causal-prefix-only replacement 或 matched donor context，而不是修改本轮 C1。

# §7 M5 增补条款 5S：刺激侧控制的统计与判读

## 7.1 分析地位

刺激侧控制全部为：诊断性；探索性；未校正；非确认性。确认性家族仍保持每被试两项，不因本增补扩大。

## 7.2 paired story bootstrap

沿用 M5 机制：每被试独立；1000 次；outer fold 内 story resampling with replacement；同一次 bootstrap draw 在以下维度共享同一批 story indices——normal 与 C1/C2、所有模型、H=8/128（如执行含 H=32）；Fisher-z 聚合；valid-TR weighting；固定 bootstrap seed；bootstrap 只作用于已生成的 story-level scores，不重跑 language model、PCA 或 Ridge。

bootstrap indices 必须落盘并写入 manifest。

## 7.3 报告量

全部基于 `Δr_total = r128 − r8`，主层、left IFG、逐被试。

### A. 控制条件下的模型内增益

对每个模型 `m`：`Δr_total^C1(m)`，报告点估计与 95% CI。

### B. normal 与 C1 的模型内配对差值

```text
D_m = Δr_total^normal(m) − Δr_total^C1(m)
```

报告点估计与 95% CI。

### C. C1 条件下的架构差值

```text
A_MP^C1 = Δr_total^C1(Mamba) − Δr_total^C1(Pythia)
A_RP^C1 = Δr_total^C1(RWKV)  − Δr_total^C1(Pythia)
```

报告点估计与 95% CI。

### D. 关键交互对比：difference-in-differences

这是刺激侧控制最关键的诊断性统计量：

```text
I_MP =
[Δr_total^normal(Mamba) − Δr_total^normal(Pythia)]
−
[Δr_total^C1(Mamba)     − Δr_total^C1(Pythia)]
```

等价于 `I_MP = D_Mamba − D_Pythia`。它直接回答：

> Mamba 相对 Pythia 的 Context Gain 优势，在真实上下文结构被破坏后是否减弱。

如 M4S-Core 包含 RWKV，也可报告：

```text
I_RP = D_RWKV − D_Pythia
```

所有量均标注 `diagnostic, uncorrected, non-confirmatory`。

### E. 精度与功效预声明（结果产出前写死）

`I_MP` 是由上下文差值、架构差值与条件差值构成的**三级嵌套对比**：其基础量级由已知的 normal 结果决定——`Δr_total` 约 0.0006–0.0069，`A_MP^normal` 约 +0.0014 至 +0.0044。`I_MP` 是在此之上再取一次差，且每一层都携带 bootstrap 不确定性。因此**预期 `I_MP` 的 CI 会较宽，检出力偏低**。

由此预先约定：

1. 报告 `I_MP` 时必须同时给出点估计、95% CI **与 CI 宽度**，并与 `A_MP^normal` 的量级并列呈现，供读者判断精度；
2. 一并报告 bootstrap 分布的标准差；
3. **`I_MP` 的 CI 跨 0 一律解释为"在当前故事级样本数量及观测变异下，诊断性交互的估计精度不足，尚不能可靠判断其方向"**，不解释为"无交互效应"；相应地，也不得据此声称主结论已被证伪；
4. 不因 `I_MP` 不显著而增加 bootstrap 次数、更换聚合方式或改变 ROI —— bootstrap 次数不改变有效样本量（每折 27–28 篇故事），增加次数只会让 CI 更稳定而非更窄；
5. 本条第 3、4 项与 §7.4 判读表相应行同时生效。

## 7.4 结果产出前冻结的判读规则

本节必须在查看 M4S held-out 结果前写入配置并打 tag。

| 观测模式 | 允许写出的结论 | 必须同时保留的限制 | 不允许写出的结论 |
|---|---|---|---|
| 某模型 `D_m > 0`，且 95% CI 不跨 0 | 该模型的 Context Gain 对完整同故事语言结构具有敏感性，不容易仅由名义输入长度解释；§2.4 的偏差方向与该结论相反，故该结论相对稳健 | C1 为 OOD 输入；下降可能包含表示退化和统计结构变化；若 §2.3 主指标显示退化随 H 加剧，须进一步下调 | 不得声称已证明特定句法、语义或指代成分的贡献 |
| 某模型 `D_m` 接近 0 或 CI 跨 0 | 当前控制没有提供明确证据说明该模型的 Context Gain 依赖完整上下文结构 | 必须同时报告 §2.4 的 origin inclusion / form repetition 量级，并说明该偏差正是朝此方向起作用；不能把"未显著"解释为两条件完全等价 | 不得隐去或改 seed 后重跑以追求显著；不得据此断定 Context Gain 与语言结构无关 |
| 某模型 `D_m < 0`，且 CI 不跨 0（C1 下增益反而高于 normal） | 该模型的 Context Gain 在打乱上下文下不降反升，现有增益的语言学解释不成立，须在 Results 与 Discussion 中如实呈现 | 须同时检查 evr@100、有效维度、lag-1 与 §2.4 量级：更平滑、有效维度更低的特征可能更受 ridge 偏好，词形重复也可能提供长窗口专属线索 | 不得把该模型从分析中剔除，也不得只报其余模型 |
| `I_MP > 0`，且 95% CI 不跨 0 | 支持 Mamba 相对 Pythia 的 Context Gain 优势更依赖完整上下文结构 | 仍是 checkpoint-level、diagnostic evidence；§2.4 偏差在两模型上的抵消是否完全无法验证 | 不得升级为 Mamba 机制与大脑机制相同 |
| `I_MP` 接近 0 或 CI 跨 0 | 在当前故事级样本数量及观测变异下，交互估计精度不足，尚不能可靠判断方向（见 §7.3E） | normal 显著、C1 不显著不等于 interaction 显著；同时也不等于交互不存在 | 不得仅通过比较两个 p 值声称优势消失；也不得声称主结论已被证伪 |
| `I_MP < 0`，且 CI 不跨 0 | 扰动后 Mamba−Pythia 差异未减弱、甚至扩大；主结论的语言历史解释必须明显弱化 | 需讨论模型对 OOD 输入的差异鲁棒性 | 不得撤下分析或更换控制条件替代结果 |
| C1 与 C2 差异明显 | 可描述结果对"局部词汇来源是否保留"具有敏感性 | C1/C2 同时改变多个因素，且 block=256 只是弱意义上的局部保留（§0.4） | 不得声称已经分离句法与词汇内容的独立因果贡献 |

### 纪律条款

- 不以"一个条件显著、另一个不显著"代替条件间直接对比；
- 不因控制结果不利而更换 seed、ROI、层、H 或模型；
- 不因 C1 结果不利而只报告 C2；
- 不因 C2 结果更有利而把 C1 从正文删除；
- 不因 `I_MP` 不显著而扩大 bootstrap 次数或改变聚合口径；
- 不在 `D_m` 接近 0 时省略 §2.4 的偏差方向说明；
- 所有已执行条件必须在论文或 supplement 中完整披露。

## 8.9 Limitations 5.5.1 改动

新增限制：

1. C1/C2 是非自然、分布外输入；
2. 模型可能因 OOD 而整体表示退化；
3. **若 OOD 退化程度随 H 增加而累积，则退化本身是 H 依赖的，会进入 `Δr_total^C1`，配对差值 `D_m` 与交互量 `I_MP` 均不能将其消除**；§2.3 的诊断用于评估这一风险，若未执行须明确注明未经检查；
4. C1 可能使用原故事更晚位置来源词，因此不是严格 causal history，也不单独控制 story-position effect；
5. lag-1 变化可能反映语言结构破坏，也可能反映表示统计变化；lag-1 的异常判定基于事前冻结的描述性容差带，不是显著性检验；
6. `I_MP` 为三级嵌套对比，检出力有限，CI 跨 0 不构成交互不存在的证据；
7. C1/C2 不能独立分离句法、语义和词汇贡献；C2 的 block=256 只是弱意义上的局部保留；
8. C1 的固定全故事置换会使目标 occurrence 的原始位置或相同词形进入控制窗口，且该概率随 H 上升（H=128 时高频词几乎必然出现）；该效应**系统性地压低 `D_m`**，方向与"控制生效"相反；§2.4 只量化该风险，不通过事后排除目标词消除它；其在 `I_MP` 上的抵消是否完全无法验证；
9. OOD 诊断中，表示层退化以 L2 范数与有效维度为主指标；目标词 NLL 仅作辅证，因其同时受"上下文信息量下降"与"输入 OOD 退化"影响，无法区分二者。

## 8.10 Future Work 5.5.2 改动

如 M4S 已执行，删除"未来可增加简单上下文打乱控制"的表述，改为更细粒度的控制：只替换人名 / 指代词；只打乱功能词；句内 vs 跨句扰动；**matched perplexity control 与 in-distribution paraphrase control（直接针对本轮的 OOD 混淆）**；**causal-prefix-only replacement 或 matched donor context（直接针对 §2.4 的词形重复混淆）**；block 尺度系统扫描；language-phenomenon-stratified scoring。

## 8.11 Abstract 改动

只有在结果足够清楚且篇幅允许时，追加一句刺激侧控制结果。优先级：保留主结果 → 保留 time-shift → 再考虑 stimulus-side control。不得在摘要中把 diagnostic control 写成第二个确认性主结论。

# 附录 B：本版（V6.4.2）相对 V6.4.1 的变更点

V6.4.1 的主设计、确认性家族、M4S 位置、C1/C2 规范、`D_m`、`I_MP`、§2.3/§2.4 两项诊断的存在与降级路径均**保持不变**。本版只做以下五处修订：

**B.1 修正 lag-1 参考带的统计性质（§2.2，必须改）**

V6.4.1 以"normal story-level 中位数的 bootstrap 2.5/97.5 百分位"作为异常判定带。该区间是**精度区间**，随故事数增大而收窄；而 C1 相对 normal 的 lag-1 位移是设计上预期会发生的真实变化。两者尺度不匹配，会导致审计标记近乎必然触发、随后被普遍忽略，闸门失效。

本版改为：以 **normal 条件 story-level 值本身的分布**（中位数、SD、2.5/97.5 percentiles）作容差带用于判异常；bootstrap 区间保留但明确降级为描述性精度区间；新增**逐故事配对差值 `Δlag1`** 作为主报告量；审计触发规则三条与阈值 `k = 1.0` 事前冻结。相应条目并入 §4.8、§5.10、§6.10、§8.6、§8.9.5 与 §11。

**B.2 §2.4 补入预期量级表与偏差方向声明（§2.4，强烈建议）**

V6.4.1 要求记录 origin inclusion / form repetition，但未给出预期量级、也未声明偏差方向。本版补入：

- 解析预期式 `E[origin_inclusion_rate] ≈ H/N`、`E[form_repetition_rate | f] ≈ 1−(1−H/N)^f`，及按平均故事长度 `N ≈ 1,889` 的量级表（H=128 时 origin ≈ 6.8%，高频词 form repetition ≈ 97%）。该表同时承担**实现自检**功能：实测大幅偏离即提示置换/索引实现有误；
- **偏差方向声明**：该效应抬高 `r128^C1` → 抬高 `Δr_total^C1` → **压低 `D_m`**，即系统性偏向"控制未生效"的结论。因此 `D_m` 显著为正时结论更稳；`D_m` 接近 0 时不得直接断定不依赖语言结构。`I_MP` 上的抵消是否完全无法验证。
- 相应条目并入 §7.4 判读表第 2、3、4 行、§7.7、§8.5、§8.9.8 与 §11。
- 同时在 §0.3 新增**索引记号约定**（`context_slots` / `context_origins` / `context_words` 三者不得混用），消除 §2.4 公式的实现歧义。

**B.3 §2.3 指标主次调整与 NLL 纪律理由修正**

- 将 **L2 范数与有效维度**定为表示层退化的主指标，NLL 降为辅助指标，理由是 NLL 同时受"上下文信息量下降"（正是本控制想造成的效果）与"OOD 退化"（混淆项）影响，无法区分二者；判读中新增"仅 NLL 变化更大"的弱化处理分支。
- 修正禁止跨架构 NLL 排名的**理由**：V6.4.1 的表述暗示概率不可比，但 Pythia、RWKV-4 与 Mamba 共用 GPTNeoX tokenizer 与词表，事件空间相同，原理上可比。本版改为"该量不进入任何 contrast、与 `D_m`/`I_MP` 无关，报告只会引入无关分歧"，并明确禁止以"词表不同"为由解释该纪律。
